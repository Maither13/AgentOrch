**静态核对发现的 3 个风险点（需执行后确认，暂不定级为 bug）：**

1. **`response_model` 与手动 `JSONResponse` 并存**：`/add` 声明 `response_model=AddResponse`（`result/a/b` 均为 `float`），但函数返回 `JSONResponse`。FastAPI 对直接返回 `Response` 的路径**跳过** `response_model` 序列化，因此 `{"a":1,"b":2}` 实际返回 `result: 3`（int）而非 `3.0`。TC1 断言 `== 3` 仍通过，但 `response_model` 实际未生效，OpenAPI 文档与真实响应存在类型偏差。建议开发确认是否改为返回 dict 以启用模型校验。
2. **`/add` 对 JSON 标量 body 的行为**：`validate_pair` 对非 dict 抛 `INVALID_ARGUMENT` 且**不带 `field`**。TC18 只断言 `error_code`，未断言 `field` 缺失，属覆盖不足而非实现缺陷。
3. **`NaN` 路径无用例**：`json.loads` 默认接受 `NaN`/`Infinity` 字面量，`{"a": NaN, "b": 1}` 会走 `is_number` 通过 → `add` 得 `nan` → `ensure_finite` 返回 422。该路径**未被任何用例覆盖**，且 `TestClient` 的 `json=` 参数会拒绝 NaN，需用 `content=b'{"a": NaN, "b": 1}'` 构造。

| `items` 非数组（`{"items": "abc"}` / `{"items": {}}`） | `add_batch` 有 `isinstance(items, (list,tuple))` 分支，无用例 | 补 2 条，断言 400 `INVALID_ARGUMENT`、`field == "items"` |
| `items` 恰好 100 元素（上边界） | 只测了 101（越界），未测 100（合法） | 补 100 元素用例，断言 200 且 `len(results) == 100` |
| 批量元素缺字段（`{"items":[{"a":1}]}`） | `validate_pair(index=...)` 会带 `index`，无用例 | 补 1 条，断言 400、`field == "b"`、`index == 0` |
| 并发一致性（设计 6.4） | 无共享状态，收益低 | 可选：`ThreadPoolExecutor` 并发 50 次 `/add`，断言结果全为 3 |

**结论：** 实现侧静态核对与 AC1–AC19 全部对齐，S3 自检清单中的 3 个高风险点（bool 陷阱、Content-Type 顺序、IEEE 754 严格相等）在代码中均已正确处理。测试套件 30 条用例覆盖了 P0 全部正常路径与主要边界/异常路径，但 **AC14/AC15 的执行证据仍缺失**，本轮无法给出「通过」结论。请下轮执行 `python -m pytest -v` 并回填第 3 节；同时建议开发确认第 3 节风险点 1（`response_model` 未生效）是否为预期行为。
