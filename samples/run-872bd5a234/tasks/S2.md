## 0. 需求冲突裁决（3 条待确认 + 2 条内部张力）

| # | 冲突 | 裁决 |
|---|---|---|
| C1 | `/add` 未指定 HTTP 方法 | `POST /add` + JSON body，不加版本前缀。AC12 断言 `Content-Type: text/plain` → 415，只有 POST+body 成立 |
| C2 | 浮点精度 | 严格 IEEE 754，不舍入。AC5 显式断言 `0.30000000000000004`，改精度即改需求 |
| C3 | F6/F7（P2）是否纳入 | 纳入。AC17–AC19 已可自动化，复用同一套校验，增量约 30 行 |
| **C4** | AC11 与 AC12 的隐含顺序依赖 | 固定校验顺序 `Content-Type → JSON 解析 → 字段校验 → 计算 → 有限性检查`；顺序颠倒会让 `text/plain` 的非 JSON body 误返 400 |
| **C5** | AC9 布尔值陷阱 | Python 中 `isinstance(True, int) == True`，校验必须显式先排除 `bool`，否则 `true` 被当 1 通过 |

## 1. 技术选型（3 个）
FastAPI（自带 JSON 解析 + TestClient，满足 AC14 一键 pytest）、pytest（AC14 指定）、httpx（TestClient 依赖）。不引入 DB/ORM——需求 5 节明确「无状态、不持久化」。

## 2. 模块划分（单向依赖，无环）
```
main.py → routes.py → service.py → errors.py
   └──────────┴───────────┴──→ schemas.py
```
关键决策：`service.py` 是**纯函数层，不 import FastAPI**，让 AC5 的 IEEE 754 语义可脱离 HTTP 单测，F7 的有限性检查只有一处实现。

## 3. 数据模型
需求明确无持久化，**本迭代不建表**。文档中给出可选的 `add_call_log` 审计表（P3，含 CHECK 约束与两个索引）作为未来落点，并标注不实现——这是对需求 5 节的遵循，不是遗漏。

## 4. 接口契约
逐条覆盖 AC1–AC19，每条标注实现要点与异常分支。补充了需求未列但必须处理的边界（否则违反「不返回 5xx」目标）：body 为数组/标量、`{}`、`items` 长度越界、批量元素非对象。

## 5. 关键流程
正常流 + 4 条异常流（参数非法 / 解析失败 / 并发 / 结果非有限）。并发流说明：服务无共享可变状态故无数据层冲突，`items` 上限 100 即为资源耗尽保护。

## 6. 风险与取舍（5 条，均含「为什么不选另一种」）
最值得注意的 **R2**：若用 pydantic 声明 `a: float`，它会把 `"1"` 强转 `1.0`、`true` 转 `1.0`，**直接违反 AC8/AC9**。故请求体用 `Request` 手动取 JSON + 自定义校验，`schemas.py` 只用于响应模型。

## 给下游开发的两点提醒
1. **AC9 是本项目最容易踩的坑**：`bool` 判断必须写在 `isinstance(v, (int, float))` 之前。
2. **AC5 禁止任何精度处理**：不要出现 `round()`、`Decimal`、`math.isclose`，直接 `a + b`。
