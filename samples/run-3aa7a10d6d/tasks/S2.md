## 0. 需求冲突与裁决（先读这一节）

需求文档有 3 个待确认问题 + 若干内部矛盾。以下是**裁决**，开发按裁决实现，测试按裁决断言。

| # | 冲突/缺口 | 裁决 | 依据 |
|---|---|---|---|
| C1 | 及格线口径未定（§7.1） | **`pass_line = full_score * 0.6`**，`score >= pass_line` 记为及格；`pass_rate = 及格条数 / count`，保留 4 位小数（四舍五入）。不区分缺考/缓考（本版本无该字段）。 | AC20 用 90/60/30 满分 100 得 0.6667，只有 `>=60` 成立才得 2/3，故取 60% 且含等号 |
| C2 | `semester` 是否限制未来/跨年级（§7.2） | **只校验格式 `^\d{4}-[12]$`**，不限制未来学期、不校验 `grade_year`。 | AC13 只要求格式校验；加业务限制会与 AC9/AC14 合法用例产生未定义行为 |
| C3 | 鉴权方案未定（§7.3） | **本版本用固定静态 Bearer Token**（配置项注入，不引入 JWT/密码库）。Token→角色映射见 §5.5。 | F12、AC26 |
| C4 | **矛盾**：§4.1 学生 PATCH 允许改 `class_name`，但 AC15 依赖 `class_name` 过滤成绩；§5.3 Score 未冗余 `class_name` | 成绩查询的 `class_name` 过滤**实时 JOIN students 表**，不冗余快照。改班级后历史成绩的班级归属随之变化（"当前班级"语义）。 | AC15 |
| C5 | **矛盾**：§4.3 PATCH 响应要求 `previous_score`，但 GET 单条响应字段未列该字段 | `previous_score` **仅出现在 PATCH 响应**，GET 单条不返回。 | AC17 |
| C6 | AC24 批量导入返回 200 而非 201 | 批量接口**固定返回 200**（部分成功语义），单条创建返回 201。 | AC24 vs AC9 |
| C7 | 逻辑删除 + 唯一约束：三元组仅在未删除记录中唯一，但普通 UNIQUE 索引会连已删除行一起约束 | 用**部分唯一索引** `WHERE is_deleted = 0`。删除后重新录入同一组合必须成功。 | §5.3、AC10、AC19 |
| C8 | 学号/课程编号"全局唯一"与逻辑删除的关系 | `student_no`/`course_code` 唯一性**包含已删除记录**（全局唯一，不释放）。 | §4.1/§4.2 写"全局唯一"，未限定未删除 |

## 1. 技术选型（3 个关键依赖）

| 依赖 | 版本 | 一句话理由 |
|---|---|---|
| **FastAPI** | 0.115.x | 16 个端点全是 JSON CRUD + 统一错误结构，Pydantic 校验天然产出 `VALIDATION_ERROR` 所需的 400 分支，自带 OpenAPI 便于测试 Agent 核对契约。 |
| **SQLAlchemy 2.x** | 2.0.x | 需要部分唯一索引（C7）、`AVG/MAX/MIN` 聚合（F7/F8）与事务内写锁语义（并发流），ORM 层能同时表达表结构与聚合查询。 |
| **SQLite（文件库）** | 标准库 | 单机教务场景、零运维；`WHERE` 部分索引与聚合均支持。生产换 PostgreSQL 仅需改 `DATABASE_URL`（表结构已避开 SQLite 专有类型）。 |

**明确不引入**：JWT 库、Redis、Celery、Alembic（用启动时 `create_all` + `sql/schema.sql` 作为唯一事实源）。理由：范围不含分布式与异步任务，F10 批量导入同步 200 条以内，无需队列。

## 2. 模块划分（依赖单向，禁止循环）

```

                    │  students courses scores  │  只依赖 service + schemas
                    │  statistics deps          │
                    └───────────┬──────────────┘
                                │ 单向
                    ┌───────────▼──────────────┐
                    │  services/ (业务层)        │  校验编排、事务边界、聚合计算
                    │  student course score     │  只依赖 repositories + models + errors
                    │  statistics auth          │
                    └───────────┬──────────────┘
                                │ 单向
                    ┌───────────▼──────────────┐
                    │  repositories/ (数据层)    │  纯 SQL/ORM 查询，不含业务判断
```

|---|---|---|---|

| `services/score_service.py` | 录入/查询/更正/删除/批量、唯一性、满分范围、写历史 | repositories, errors | F3–F6, F10, F11, AC9–AC19, AC24–AC25 |
| `services/statistics_service.py` | 课程统计、班级统计、成绩单聚合与舍入 | repositories | F7–F9, AC20–AC23 |
| `services/auth_service.py` | Token→角色解析、越权判定 | config, errors | F12, AC26 |
| `repositories/*` | 单表/联表查询、聚合 SQL、唯一索引冲突捕获 | models | 全部 |
| `errors.py` | `ErrorCode` 枚举 + `AppError(code, http_status, message, details)` | — | §4.6 |
| `schemas.py` | 请求/响应 Pydantic 模型 + `Page[T]` 泛型 | — | §4 字段表 |

**依赖规则（开发必须遵守）**
1. `api → services → repositories → models`，反向 import 一律禁止。
2. `errors.py` / `schemas.py` / `config.py` 不得 import 任何 `services`/`repositories`。
3. 只有 `services` 层可开启/提交事务；`api` 层不写 `db.commit()`。

## 4. 数据模型（DDL，SQLite 方言，可平移到 PostgreSQL）

```sql
-- 学生
CREATE TABLE students (
    id          TEXT    PRIMARY KEY,
    student_no  TEXT    NOT NULL,
    name        TEXT    NOT NULL,
    class_name  TEXT    NOT NULL,
    grade_year  INTEGER NOT NULL,
    status      TEXT    NOT NULL DEFAULT 'active'
                        CHECK (status IN ('active','inactive')),
    is_deleted  INTEGER NOT NULL DEFAULT 0 CHECK (is_deleted IN (0,1)),
    created_at  TEXT    NOT NULL,
    updated_at  TEXT    NOT NULL,
    CONSTRAINT ck_students_grade_year CHECK (grade_year BETWEEN 1900 AND 2100),
    CONSTRAINT ck_students_no_len     CHECK (length(student_no) BETWEEN 4 AND 20)
);

-- 学号全局唯一（含已删除记录，见裁决 C8）
CREATE UNIQUE INDEX ux_students_student_no ON students (student_no);
-- 列表过滤：class_name + status 组合查询（AC5）
CREATE INDEX ix_students_class_status ON students (class_name, status, is_deleted);
CREATE INDEX ix_students_grade_year   ON students (grade_year, is_deleted);

-- 课程
CREATE TABLE courses (
    id          TEXT    PRIMARY KEY,
    course_code TEXT    NOT NULL,
    name        TEXT    NOT NULL,
    credit      REAL    NOT NULL,
    full_score  REAL    NOT NULL DEFAULT 100,
    is_deleted  INTEGER NOT NULL DEFAULT 0 CHECK (is_deleted IN (0,1)),
    created_at  TEXT    NOT NULL,
    updated_at  TEXT    NOT NULL,
    CONSTRAINT ck_courses_credit     CHECK (credit >= 0.5 AND credit <= 10
                                            AND (credit * 2) = CAST(credit * 2 AS INTEGER)),
    CONSTRAINT ck_courses_full_score CHECK (full_score >= 1 AND full_score <= 1000)
);

CREATE UNIQUE INDEX ux_courses_course_code ON courses (course_code);
CREATE INDEX ix_courses_is_deleted ON courses (is_deleted);

-- 成绩
CREATE TABLE scores (
    id          TEXT    PRIMARY KEY,
    student_id  TEXT    NOT NULL REFERENCES students(id),
    course_id   TEXT    NOT NULL REFERENCES courses(id),
    semester    TEXT    NOT NULL,
    score       REAL    NOT NULL,
    operator_id TEXT    NOT NULL,
    is_deleted  INTEGER NOT NULL DEFAULT 0 CHECK (is_deleted IN (0,1)),
    created_at  TEXT    NOT NULL,
    updated_at  TEXT    NOT NULL,
    CONSTRAINT ck_scores_semester CHECK (semester GLOB '[0-9][0-9][0-9][0-9]-[12]'),
    CONSTRAINT ck_scores_score    CHECK (score >= 0),
    CONSTRAINT ck_scores_operator CHECK (length(operator_id) BETWEEN 1 AND 64)
);

-- 关键：部分唯一索引，只在未删除记录中唯一（裁决 C7 / AC10 / AC19）
CREATE UNIQUE INDEX ux_scores_active_triplet
    ON scores (student_id, course_id, semester) WHERE is_deleted = 0;

-- 组合条件查询（AC14/AC15/AC16/AC20/AC22）
CREATE INDEX ix_scores_student_semester ON scores (student_id, semester, is_deleted);
CREATE INDEX ix_scores_course_semester  ON scores (course_id, semester, is_deleted);
CREATE INDEX ix_scores_active           ON scores (is_deleted);

-- 成绩变更历史（只追加，不更新不删除）
CREATE TABLE score_histories (
    id             TEXT PRIMARY KEY,
    score_id       TEXT NOT NULL REFERENCES scores(id),
    previous_score REAL NOT NULL,
    new_score      REAL NOT NULL,
    operator_id    TEXT NOT NULL,
    reason         TEXT NULL,
    changed_at     TEXT NOT NULL,
    CONSTRAINT ck_hist_reason_len CHECK (reason IS NULL OR length(reason) <= 200)
);

CREATE INDEX ix_histories_score_changed ON score_histories (score_id, changed_at);
```

**设计说明（可追溯）**
- `id` 用 `TEXT`（UUID4 字符串）：§4 声明 `id` 为 `string`，AC1 只要求"非空 id"。
- 时间用 `TEXT` 存 ISO 8601 UTC（`2024-01-01T00:00:00Z`）：SQLite 无原生 datetime，序列化直接输出，满足 §4 通用约定。
- `score` 用 `REAL`：§5.3 允许 1 位小数；"最多 1 位小数"在 service 层用 `round(x,1) == x` 校验（DB 层不校验，避免浮点误差误判）。
- `score <= full_score` **不在 DB CHECK 里**（跨表约束），由 `score_service` 在事务内先读课程再校验，抛 `SCORE_OUT_OF_RANGE`（AC11）。
- `score_histories` 无 `is_deleted`：F11 要求历史可追溯，删除成绩不删历史（AC18 只统计 PATCH 次数）。

## 5. 接口契约（与 F*/AC* 逐条对应）

### 5.0 通用约定

- 前缀 `/api/v1`；`snake_case`；时间 ISO 8601 UTC。
- **分页**：`page` 默认 1、最小 1；`page_size` 默认 20、范围 1–100。越界（0 或 101）→ 400 `VALIDATION_ERROR`（AC28）。响应 `{items,total,page,page_size}`。
- **错误响应**：`{"error_code": str, "message": str, "details": object|null}`。
- **校验顺序（全局固定，否则 AC 断言不稳定）**：
  1. 鉴权（401）→ 2. 角色（403）→ 3. 路径/查询/请求体格式校验（400 `VALIDATION_ERROR`）→ 4. 资源存在性（404）→ 5. 业务规则（400 `SCORE_OUT_OF_RANGE` / 409 冲突）。
  > 例：AC12 用不存在的 `student_id` 但格式合法 → 走到第 4 步返回 404；AC13 的 `semester=2024-3` 在第 3 步被拦下返回 400。
- **错误码→HTTP 映射**（§4.6 全量，`errors.py` 硬编码）：

| error_code | HTTP | 触发点 |
|---|---|---|
| VALIDATION_ERROR | 400 | Pydantic 校验失败、分页越界、缺必填查询参数、批量条数越界 |
| UNAUTHORIZED | 401 | 无 `Authorization` 头 / token 不在白名单 |
| FORBIDDEN | 403 | 学生角色访问他人数据或非白名单端点 |
| STUDENT_NOT_FOUND | 404 | 学生不存在或 `is_deleted=1` |
| COURSE_NOT_FOUND | 404 | 课程不存在或 `is_deleted=1` |
| SCORE_NOT_FOUND | 404 | 成绩不存在或 `is_deleted=1` |
| STUDENT_NO_DUPLICATED | 409 | `student_no` 冲突 |
| COURSE_CODE_DUPLICATED | 409 | `course_code` 冲突 |
| SCORE_DUPLICATED | 409 | 未删除成绩三元组冲突 |
| SCORE_OUT_OF_RANGE | 400 | `score<0` 或 `score>course.full_score` |
| STUDENT_HAS_SCORES | 409 | 删除学生时存在未删除成绩 |
| COURSE_HAS_SCORES | 409 | 删除课程时存在未删除成绩 |

### 5.1 学生（F1）

| 端点 | 契约要点 | 需求 |
|---|---|---|
| `POST /students` | 201；`student_no`(4–20 字母数字)、`name`(1–50)、`class_name`(1–50)、`grade_year`(1900–2100)、`status`(默认 active)。响应含 `id,student_no,name,class_name,grade_year,status,created_at,updated_at`。异常：格式错→400 `VALIDATION_ERROR`；`student_no` 已存在（**含已删除**）→409 `STUDENT_NO_DUPLICATED`。实现要点：先查重再插入，同时捕获 `ux_students_student_no` 的 `IntegrityError` 兜底并发。 | AC1, AC2, AC3 |
| `GET /students/{id}` | 200；`is_deleted=1` 视为不存在→404 `STUDENT_NOT_FOUND`。 | AC4 |
| `GET /students` | 参数 `class_name`、`grade_year`、`status`、`keyword`（`student_no` 或 `name` 模糊，`LIKE %kw%`）、`page`、`page_size`。`total` 为过滤后总数（不受分页影响），`items` 长度 ≤ `page_size`。默认排除已删除。 | AC5, AC6, AC28 |
| `PATCH /students/{id}` | 200；可改 `name/class_name/grade_year/status`，至少一个，否则 400 `VALIDATION_ERROR`；`student_no` 出现在 body 中→400（不可修改）。404 `STUDENT_NOT_FOUND`。 | §4.1 |
| `DELETE /students/{id}` | 204 无体；不存在→404 `STUDENT_NOT_FOUND`；存在未删除成绩→409 `STUDENT_HAS_SCORES`。实现要点：`UPDATE students SET is_deleted=1, updated_at=now`，不物理删除。 | AC6, AC27 |

### 5.2 课程（F2）

| 端点 | 契约要点 | 需求 |
|---|---|---|
| `POST /courses` | 201；`course_code`(2–20 字母数字)、`name`(1–50)、`credit`(0.5–10 且步长 0.5)、`full_score`(默认 100，1–1000)。`credit=0` 或 `11` → 400 `VALIDATION_ERROR`；重复编号→409 `COURSE_CODE_DUPLICATED`。 | AC7, AC8 |
| `GET /courses/{id}` | 200 / 404 `COURSE_NOT_FOUND`。 | §4.2 |
| `GET /courses` | `keyword`（`course_code` 或 `name` 模糊）、分页；默认排除已删除。 | §4.2, AC28 |
| `PATCH /courses/{id}` | 可改 `name/credit/full_score`；`course_code` 不可改（出现即 400）。实现要点：**改小 `full_score` 时若已有成绩超过新满分，返回 400 `VALIDATION_ERROR`**（`details` 给出冲突成绩数），避免产生违反 AC11 不变式的存量数据。 | §4.2 |
| `DELETE /courses/{id}` | 204；404 `COURSE_NOT_FOUND`；有未删除成绩→409 `COURSE_HAS_SCORES`。 | AC27 |

### 5.3 成绩（F3–F6, F10, F11）

| 端点 | 契约要点 | 需求 |
|---|---|---|
| `POST /scores` | 201；`student_id`/`course_id` 必须存在且未删除（否则 404 对应码）；`semester` 正则 `^\d{4}-[12]$`（`2024-3`/`2024/1`→400 `VALIDATION_ERROR`）；`score` 0≤x≤`course.full_score` 且最多 1 位小数，越界→400 `SCORE_OUT_OF_RANGE`；`operator_id` 1–64。三元组已存在未删除记录→409 `SCORE_DUPLICATED`。响应 `id,student_id,course_id,semester,score,operator_id,created_at,updated_at`。 | AC9–AC13 |
| `GET /scores` | 参数 `student_id`、`course_id`、`semester`、`class_name` 全部可选可组合；`class_name` 通过 JOIN `students` 过滤（裁决 C4）。items 元素含 `id,student_id,student_no,student_name,course_id,course_code,course_name,semester,score,updated_at`。默认排除已删除。 | AC14, AC15, AC16, AC28 |
| `GET /scores/{id}` | 200；已删除→404 `SCORE_NOT_FOUND`。**不返回 `previous_score`**（裁决 C5）。 | AC16 |
| `PATCH /scores/{id}` | 200；`score` 必填（同录入约束）、`operator_id` 必填、`reason` ≤200 可选。响应 = 成绩对象 + `previous_score`。实现要点：**同一事务内**先加写锁读旧值 → 校验范围 → `UPDATE scores` → `INSERT score_histories(previous_score,new_score,operator_id,reason,changed_at)` → commit。`score` 与旧值相同也写一条历史（AC18 以"更正次数"计数）。 | AC17, AC18 |
| `DELETE /scores/{id}` | 204；已删除/不存在→404 `SCORE_NOT_FOUND`（AC19 二次删除）。逻辑删除，**不删历史**。 | AC19 |
| `GET /scores/{id}/histories` | 200 `{"items":[{changed_at,operator_id,previous_score,new_score,reason}]}`，按 `changed_at ASC` 排序（最新在末尾，AC18 断言"最新一条"取 `items[-1]`）。成绩不存在→404 `SCORE_NOT_FOUND`。 | AC18, F11 |
| `POST /scores/batch` | **200**（裁决 C6）；`records` 1–200 条，空或 >200→400 `VALIDATION_ERROR`；`operator_id` 必填。逐条独立事务（savepoint），单条失败不影响其他条。响应 `{succeeded,failed,results:[{index,status,score_id,error_code}]}`，`index` 从 0 开始。 | AC24, AC25 |

### 5.4 统计与成绩单（F7–F9）

| 端点 | 契约要点 | 需求 |
|---|---|---|
| `GET /statistics/courses/{course_id}` | 参数 `semester` 可选。响应 `course_id,semester,count,average,max,min,pass_rate,pass_line`。`pass_line = full_score*0.6`（裁决 C1）；`average` 保留 2 位小数（`ROUND_HALF_UP`）；`pass_rate` 保留 4 位小数。**`count=0` 时 `average/max/min/pass_rate` 全为 `null`，HTTP 200**（AC21）。课程不存在→404 `COURSE_NOT_FOUND`。 | AC20, AC21 |
| `GET /statistics/classes/{class_name}` | `semester` **必填**，缺失→400 `VALIDATION_ERROR`。响应 `class_name,semester,student_count,average,pass_rate`。`student_count` = 该班该学期有未删除成绩的**去重学生数**；`average` = 该班该学期所有未删除成绩的算术平均（2 位小数）；`pass_rate` = 及格成绩数 / 成绩总数（4 位小数）。空集同样返回 `null` 而非报错。 | AC22 |
| `GET /students/{id}/transcript` | `semester` 必填（缺失→400 `VALIDATION_ERROR`）；学生不存在→404 `STUDENT_NOT_FOUND`。响应 `student_id,student_no,student_name,semester,items[{course_id,course_code,course_name,credit,score,full_score}],average,total_credit`。`average` = items 中 `score` 算术平均（2 位小数，空集为 `null`）；`total_credit` = items 的 `credit` 之和。 | AC23 |

### 5.5 鉴权与权限矩阵（F12）

**方案（裁决 C3）**：`Authorization: Bearer <token>`，token 为配置项 `AUTH_TOKENS` 中的静态字符串，映射到主体 `{role, student_id?}`。不引入 JWT。

| token（测试固定值） | role | 绑定 student_id |
|---|---|---|
| `token-admin` | `admin`（教务） | — |
| `token-teacher` | `teacher` | — |
| `token-student-1` | `student` | `stu-1` |
| `token-student-2` | `student` | `stu-2` |

**权限矩阵**

| 端点 | admin | teacher | student |
|---|---|---|---|
| 学生/课程 全部写操作（POST/PATCH/DELETE） | ✅ | ❌ 403 | ❌ 403 |
| 学生/课程 GET | ✅ | ✅ | ❌ 403 |
| `POST /scores`、`PATCH/DELETE /scores`、`/scores/batch` | ✅ | ❌ 403 | ❌ 403 |
| `GET /scores` | ✅ | ✅ | ⚠️ 仅当 `student_id` 等于自身，否则 403 `FORBIDDEN`（AC26）；**未传 `student_id` 时强制注入自身 id** |
| `GET /scores/{id}` | ✅ | ✅ | ⚠️ 该成绩 `student_id` 必须等于自身，否则 403 |
| `GET /scores/{id}/histories` | ✅ | ✅ | ⚠️ 同上 |
| `GET /statistics/*` | ✅ | ✅ | ❌ 403 |
| `GET /students/{id}/transcript` | ✅ | ✅ | ⚠️ 仅本人，否则 403 |

**实现要点**：`api/deps.py` 提供 `get_current_principal`（解析 token，失败→401 `UNAUTHORIZED`）与 `require_roles(*roles)`；学生越权判定放在 `score_service`/`student_service` 内（需 `student_id` 与资源比对），统一抛 `FORBIDDEN`。**401 优先于 403**：无 token 时任何端点都返回 401（AC26 后半句）。

## 6. 关键流程

### 6.1 正常流：录入成绩（F3 / AC9）

```
POST /api/v1/scores
 1. deps: 解析 Bearer token → principal(role=admin)          [失败 → 401 UNAUTHORIZED]
 2. deps: require_roles(admin)                                [失败 → 403 FORBIDDEN]
 3. Pydantic: semester 正则、operator_id 长度、score 为 number [失败 → 400 VALIDATION_ERROR]
 4. score_service.create:
    4.1 student_repo.get_active(student_id)                  [None → 404 STUDENT_NOT_FOUND]
    4.2 course_repo.get_active(course_id)                    [None → 404 COURSE_NOT_FOUND]
    4.3 0 <= score <= course.full_score 且 round(score,1)==score
                                                             [失败 → 400 SCORE_OUT_OF_RANGE]
    4.4 score_repo.get_active_by_triplet(...)                [存在 → 409 SCORE_DUPLICATED]
    4.5 INSERT scores(...) → commit                          [IntegrityError(ux_scores_active_triplet)
                                                               → 409 SCORE_DUPLICATED]
 5. 201 + 成绩对象
```

### 6.2 异常流 A：参数非法（AC13 / AC28 / AC3）

```
GET /api/v1/scores?page_size=101
 1. 鉴权通过
 2. pagination 依赖校验 page_size ∈ [1,100] → 400 VALIDATION_ERROR
    details = {"field": "page_size", "reason": "must be between 1 and 100"}
 → 请求不进入 service 层，不产生任何 DB 访问

POST /api/v1/scores  body.semester = "2024-3"
 1-2. 鉴权通过
 3. Pydantic pattern 不匹配 → 400 VALIDATION_ERROR
    details = {"field": "semester", "reason": "must match YYYY-S with S in {1,2}"}
 → 不查库，不返回 404（即使 student_id 也不存在）
```
**要点**：所有 400 由 `RequestValidationError` 处理器统一改写为 `VALIDATION_ERROR` 结构，`details` 至少含 `field`。

### 6.3 异常流 B：依赖失败 / 引用完整性（AC12 / AC27）

```
DELETE /api/v1/students/{id}   （该学生有未删除成绩）
 1-2. 鉴权 + 角色通过
 3. student_repo.get_active(id)                [None → 404 STUDENT_NOT_FOUND]
 4. score_repo.count_active_by_student(id) > 0 [→ 409 STUDENT_HAS_SCORES,
                                                details={"active_score_count": n}]
 5. 不执行 UPDATE，事务回滚
```
**要点**：检查与更新在**同一事务**内，且 `UPDATE students SET is_deleted=1` 前再次确认无成绩，避免检查后插入的竞态（见 6.4）。

### 6.4 异常流 C：并发冲突（AC10 / AC17）

```
两个请求同时 POST /scores 同一 (student_id, course_id, semester)
 T1: BEGIN IMMEDIATE → 查无记录 → INSERT → COMMIT
 T2: BEGIN IMMEDIATE → 查无记录 → INSERT → COMMIT
     ↑ 第二个 COMMIT 触发 ux_scores_active_triplet 唯一索引冲突
     → 捕获 IntegrityError → 409 SCORE_DUPLICATED
 → 最终该三元组未删除记录数 = 1（AC10 断言成立）

两个请求同时 PATCH /scores/{id}
 T1: BEGIN IMMEDIATE → 读旧值 80 → UPDATE 90 → INSERT history(80→90) → COMMIT
 T2: BEGIN IMMEDIATE（等 T1 释放）→ 读旧值 90 → UPDATE 95 → INSERT history(90→95) → COMMIT
 → histories 条数 = 2，无丢失更新（AC18 断言成立）
```
**要点**
- 唯一性**必须**由 DB 部分唯一索引兜底，不能只靠"先查后插"（AC10 要求"记录数仍为 1"）。
- `PATCH` 的读-改-写必须串行化：SQLite 用 `BEGIN IMMEDIATE`（写锁前置），PostgreSQL 用 `SELECT ... FOR UPDATE`。`db.py` 提供 `write_transaction()` 上下文管理器统一封装。
- 批量导入每条记录用 `SAVEPOINT`，单条 `IntegrityError` 只回滚该条（AC24）。

## 7. 风险与取舍

| # | 风险 / 取舍 | 选择 | 为什么不选另一种 | 追溯 |
|---|---|---|---|---|
| R1 | **逻辑删除 + 唯一约束的实现方式** | 部分唯一索引 `WHERE is_deleted=0` | 备选 A：应用层"先查后插"——并发下会插入两条，直接违反 AC10"记录数仍为 1"。备选 B：把 `is_deleted` 拼进唯一键 `UNIQUE(student_id,course_id,semester,is_deleted)`——删除两次后无法再录入（两条 `is_deleted=1` 冲突），违反 AC19 后重新录入的隐含场景。 | AC10, AC19, §5.3 |
| R2 | **`class_name` 不冗余到 scores** | 查询时 JOIN `students` | 备选：录入时快照 `class_name` 到 scores。优点是可保留历史班级归属，但会让 AC15（"每条记录对应学生的 class_name 均为 X"）在改班后产生歧义，且与 §5.3 字段表不符（需求未列该字段）。按"当前班级"语义实现，成本最低且可断言。 | AC15, 裁决 C4 |
| R3 | **统计在 SQL 里算 vs 应用层算** | SQL 聚合（`COUNT/AVG/MAX/MIN`）+ 应用层做 `pass_rate` 与舍入 | 备选：全量拉明细到 Python 再算。数据量小时两者等价，但全量拉取在班级/课程规模增长后是 O(n) 内存开销；且 `pass_rate` 需要与 `pass_line` 比较，SQL 里写 `SUM(CASE WHEN score >= :pass_line THEN 1 ELSE 0 END)` 同样一行可读。舍入仍放应用层，避免不同 DB 的 `ROUND` 行为差异导致 AC20 的 `0.6667` 不稳定。 | AC20, AC21, AC22 |
| R4 | **静态 Token 而非 JWT** | 配置项白名单 | 备选：JWT + 签发端点。需求 §4 未定义登录/签发端点，F12 只要求"区分三类角色 + 越权 403 + 无凭证 401"（AC26）。引入 JWT 会新增 1 个未在需求中的端点与密钥
